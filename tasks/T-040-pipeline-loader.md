## Why this task, and not T-026

The first queue entry whose `Depends on:` is met is **T-026** (§C). It was
skipped: its Done-when is "at least one new topic reaches the app end to end —
generated, **loaded**, selectable at Setup, and answerable", and nothing loads a
generated question into the served bank until this task lands. So T-026's
`Depends on:` is incomplete in the same way T-064's was, and T-040 is the
blocker. `PROGRESS.md` "Next" names T-040 first for the same reason. The note is
added to T-026's entry in `tasks.md`.

## Goal

Make the curated 50-state pipeline bank, and the questions generated from it,
what the app actually serves — replacing the 15 states and 26 questions that
were hand-copied into `backend/app/data/content.json` in PR #16. A child can then
meet all 50 states, and every curation task upstream becomes visible.

## Survey — what is already true

- **Startup loading exists and is idempotent.** `store.ensure_content_loaded`
  (`backend/app/store.py:88`) reads `backend/app/data/content.json`, keys on a
  `content_version` derived from a sha256 of the file plus `_source.extractedAt`,
  and on a version change deletes every `EntityRow`/`QuestionRow` and reinserts.
  Called from `backend/app/main.py:61`. Re-running with an unchanged file is
  already a no-op. The Docker image copies only `backend/` (`Dockerfile`), so the
  file the server loads at startup must live under `backend/`.
- **The question stages exist, are pure and deterministic, and nothing runs them
  end to end or writes their output.** `generate` → `buildChoices` →
  `seedLevels` → `tagQuestions` (`question-bank/src/{generate,distractors,
  seed-level,tags}.ts`; each documents "no clock, no randomness") give 150
  questions over the committed bank: 50 × `tpl-identify-on-map` (`map_identify`,
  topic `location`), 50 × `tpl-capital-of` (`multiple_choice`, topic
  `capital`), 50 × `tpl-click-the-map` (`map_click`, topic `location`). E-23:
  "Nothing in the build imports it".
- **Shapes do not match.** The pipeline entity is snake_case (`geometry_id`,
  `population_rank`, `fun_facts: [{text, source_url, reviewed}]`, …; e.g.
  `question-bank/data/us-states/us-state-la.json`). Everything that reads a
  payload is camelCase: `grading.build_reveal` (`backend/app/grading.py:198`)
  reads `entity.funFact`, `entity.funFactDetail`, `entity.geometryId`,
  `question.highlightGeometryId`, `question.reveal`, and only adds
  `mapHighlightGeometryId` to a *correct* reveal when `question.reveal ==
  "map_highlight"`. Generated questions carry no `reveal`.
- **Generated questions carry fields the contract does not.** A tagged question
  has `answer` and, on `map_click`, `answerGeometryId` and `choiceGeometryIds`.
  `serializers.question_payload` (`backend/app/serializers.py:21`) passes the
  stored payload through and only strips `correctIndex`, so a stored `answer`
  would hand the child the answer even with `includeAnswerKey=false`.
- **Pipeline fields with no `Entity` slot:** `state_animal`, `highest_point`,
  `highest_point_m`, `sources`. `landmark` is present on 44 of 50 states.
  Every state has exactly one `fun_facts` entry and all 50 are `reviewed: true`.
- **Entity ids differ for one state.** `content.json` serves Louisiana as
  `us-state-lo`. The demo profile (`store.py:504`) is keyed on `us-state-co`,
  `us-state-fl`, `us-state-tx`, which exist in both banks.
- **The client renders two formats.** `frontend/src/components/Session.tsx`
  branches only on `map_identify` (line 203) and `multiple_choice` (line 212).
- **`openapi.yaml:1489`** `topLivestock.description` still reads "Empty where no
  state has an honest standout" — the slip T-068's reviewer filed here.
- **`backend/app/data/content.json` is unchanged since `aa88101`**
  (`git diff aa88101 HEAD -- backend/app/data/content.json` is empty).

## Acceptance criteria

"The served bank" means what the API serves after the server starts against the
committed files on this branch. "Committed inputs" means
`question-bank/data/us-states/` as committed. Pipeline counts quoted below (50,
100, 150) are today's committed data; each criterion states the rule they come
from.

### Committed question output (Q2)

1. A command run from `question-bank/` with `bun run <script>`, documented in
   `conventions.md` "Commands", writes every question that `generate` →
   `buildChoices` → `seedLevels` → `tagQuestions` produce from the committed
   inputs to one tracked JSON file under `question-bank/data/` (path named in
   `conventions.md`). Today that file holds 150 questions, including the 50
   `map_click` ones.
2. That command makes no network request and reads no clock: run twice on an
   unchanged tree, the file is byte-identical both times and `git status` shows
   no change.
3. A `bun test` test in `question-bank/` fails when the committed question file
   differs from what the stages produce from the committed inputs (shown by the
   test, or a companion test, against an input with one entity field changed).

### The served bank (Q1)

4. A command documented in `backend/README.md` and `conventions.md` "Commands",
   run with `uv run` or `make -C backend <target>`, writes
   `backend/app/data/content.json` from the committed inputs and the committed
   question file. Running it twice on an unchanged tree leaves the file
   byte-identical and `git status` clean.
5. A `make -C backend test` test fails when the committed
   `backend/app/data/content.json` differs from what that command would write
   from the committed inputs.
6. `GET /api/v1/content/version` reports `counts.entities` = 50 and
   `counts.questions` = 100.
7. `GET /api/v1/entities` returns exactly the 50 ids listed in
   `question-bank/data/us-states/index.json` — among them `us-state-la`, and not
   `us-state-lo`.
8. For every served entity, `id`, `type`, `scope`, `name`, `capital`, `region`,
   `geometryId`, `centroid`, `population`, `populationRank`, `areaKm2`,
   `areaRank`, `borders`, `climateKid`, `landmark`, `topCrops` and
   `topLivestock` equal the pipeline file's `id`, `type`, `scope`, `name`,
   `capital`, `region`, `geometry_id`, `centroid`, `population`,
   `population_rank`, `area_km2`, `area_rank`, `borders`, `climate_kid`,
   `landmark`, `top_crops` and `top_livestock`.
9. A pipeline value that is absent or `null` is absent from the served entity
   (not `null`, not `""`): checked on `landmark` for the 6 states without one.
   An empty list is served as `[]`: checked on `topLivestock` (26 states).
10. No served entity or question carries a key that is not a property of
    `openapi.yaml`'s `Entity` or `Question` schema respectively. In particular
    no served question has `answer`, `answerGeometryId` or `choiceGeometryIds`,
    and no served entity has `stateAnimal`, `state_animal`, `highestPoint`,
    `highest_point_m`, `sources`, or any snake_case key.
11. The served question ids are exactly the ids of the questions in the
    committed question file whose `format` is not `map_click` — 100 today: one
    `map_identify` (`topic: location`) and one `multiple_choice`
    (`topic: capital`) for each of the 50 entities.
12. No served question has format `map_click`; `GET /api/v1/questions` with
    `format=map_click` (or with no filter, `limit` ≥ 100) returns none.
13. Every served question's `prompt`, `choices`, `correctIndex`, `level`,
    `topic`, `scope`, `entityType`, `region` (absent where the file omits it),
    `ageBand`, `templateId` and `highlightGeometryId` (absent where the file
    omits it) equal that question's values in the committed question file.
14. Every served question validates against `Question` in
    `backend/app/models.py`, has exactly 4 `choices`, `correctIndex` in 0–3, and
    `choices[correctIndex]` equal to the committed file's `answer` for it.
15. `GET /api/v1/questions/{id}?includeAnswerKey=false` for any served question
    returns no `correctIndex` and no field whose value is that question's
    correct choice other than inside `choices`.

### Prose — unreviewed text never ships

16. A served entity's `funFact` is the `text` of the first `fun_facts` entry, in
    array order, with `reviewed: true`.
17. Given an input state whose only `fun_facts` entry is `reviewed: false`, the
    state is still served, with no `funFact`, and that entry's `text` appears in
    no served field of any entity or question (and not in a served `funFacts`
    list, if the loader serves one).
18. Given an input state with two entries, the first `reviewed: false` and the
    second `reviewed: true`, the served `funFact` is the second's text and the
    first's text appears nowhere in the served bank.
19. No served entity has `funFactDetail` or `kidHook`, and no served question
    has `shortExplanation` or `detailExplanation` — the loader writes no prose
    of its own.

### Reveals

20. Answering a served `map_identify` question correctly returns a reveal whose
    `mapHighlightGeometryId` is its entity's `geometryId` and whose `headline` is
    its entity's `funFact`.
21. Answering a served `multiple_choice` capital question correctly returns a
    reveal with no `mapHighlightGeometryId` (as the hand-written capital
    questions did, `reveal: "none"`), and `headline` equal to the entity's
    `funFact`.
22. Answering any served question wrongly returns a reveal whose `headline` is
    `"The answer is <choices[correctIndex]>."`, whose `answerLabel` is
    `choices[correctIndex]`, and whose `mapHighlightGeometryId` is the entity's
    `geometryId`.

### Loading

23. Starting the server twice against the same committed `content.json` leaves
    `content_version`, every entity row and every question row unchanged.
24. Loading a `content.json` whose one entity field differs changes
    `content_version`, serves the new value, and leaves no entity or question
    whose id is absent from the new file.
25. With a fresh profile that answers every question correctly, the first 50
    questions of a session on topic `location` are 50 distinct ids, one per
    entity, all `map_identify`; on topic `capital`, likewise all
    `multiple_choice`; and the first 100 of a `mixed` session are 100 distinct
    ids, every one `map_identify` or `multiple_choice`.

### The hand-written bank (Q1)

26. `archive/hand-written-bank/content.json` exists and is byte-identical to
    `git show aa88101:backend/app/data/content.json`.
27. No file under `backend/app/`, `frontend/src/` or `question-bank/src/` other
    than a test reads `archive/` — the archived bank is never served.
28. `conventions.md` "Layout" names `archive/` and says it holds the retired
